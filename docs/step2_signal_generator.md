### 2. 动态截面清洗 `valid_cross_section(df_day)`

- 逐日处理。每日常规截面 = 当日指标齐备的标的（动量 RS20/RS60、量能、高风险列均非 NaN）。
- 自动剔除：未上市标的（上市日之前无数据 → 自然落在 NaN 期）、预热期（前 60 天动量/波动未齐备）。

### 3. 因子标准化与综合打分 `compute_daily_scores(df_day)`

对当日有效截面，按 3 步打分：

```
① 动量分 S_mom = 0.6 × Rank_pct(RS20) + 0.4 × Rank_pct(RS60)     ∈ (0, 1]
② 信号加分 S_signal = 0.15 × [vol_impulse > 1.3] + 0.20 × [divergence_20 == 1]
③ 风险惩罚 P_risk = 0.10 × Rank_pct(vol20_annual) + 0.10 × clip(|dd60|/60, 0, 1)

最终得分 score = S_mom + S_signal − P_risk                            ∈ (−0.2, 1.35)
```

- 横截面分位（`rank(pct=True)`）面向**当日全部有效标的**计算，取每日相对强弱而非绝对截断。
- 波动率惩罚用横截面分位：高波相对扣分，非绝对值硬阈值。
- 回撤惩罚用深度绝对值（封顶 60%）：跌得越深罚越重。
- 加分/惩罚叠加后取自然分数，不强制归一（保留相对排序可比性）。

### 4. 防守态判断 `detect_regime(df_scored)`

基于进攻组（非防守）的组级动量，判定 3 态：

| regime | 条件 | 动作 |
|--------|------|------|
| `normal` | 存在进攻组 RS20>0 或 RS60>0 | 正常选 Top N |
| `mixed` | 进攻组全部 RS<0，但存在 R20>0 | **50% 防守** + 50% 进攻击组最高分 |
| `risk_off` | 进攻组全部 R20<0 且 RS<0 | `**100% 防守小组（512890）**` |

> 语义：进攻组全部相对跑输大盘（RS<0）时不再硬选进攻；若绝对动量尚可（R20>0）留半仓进攻搏反弹，否则全退防守。

### 5. 主题去重与权重分配 `select_portfolio(df_scored, regime)`

- **组内去重**：同一主题组内**最多选 1 只**（取组内最高分）。避免同主题两只一起压仓。
- **正常态**：按 score 降序，跨组选 Top N（默认 3），每只等权 1/N。防守组仅在进攻空仓时兜底。
- **mixed**：512890 恒持 0.5，进攻组最高分者 0.5。
- **risk_off**：全仓 512890（weight=1.0）。

### 6. 全历史产出 `generate_signals(start_date)`

长表 DataFrame，每行 = (date, etf_code, etf_name, group, weight, score, regime, 因子明细列)。

## 五、本轮新增的设计取舍（供 Step 3 考量）

1. **组内必选机制 vs 风险**：半导体组(159516)等单标的组，即使当日深回撤(-64%)、高波动、弱 RS，仍被"组内最高分"保送入选。这是**主题代表权 vs 风险约束**的权衡。若要强化风控，可在后续给 P_risk 设一个硬阈值（如 score 低于 0.25 则该组本轮空缺）。—— **建议 Step 3 回测时对比：有/无该保送机制的表现差异。**
2. **top N 等权**：现为 Top N 内等权（1/N），未做得分归一权重。Step 3 可测试按 score 线性加权是否更优。
3. **防守态阈值**：`RS<0 且 R20<0` 判 risk_off、`RS<0 且 R20>0` 判 mixed —— 阈值可调，回测可做敏感性。

## 六、给 Step 3 的接口提示（供大模型指导下一步）

- **直接复用**：`generate_signals(start_date)` 返回的 hist 长表可直接喂入回测引擎做净值曲线。
- **每日组合 = hist[date == d]**上的 `(etf_code, weight)`；再用 `fund_price`（收盘价）做 T+1 调仓回放（避免当日收盘价买入的未来函数）。
- **换仓频率**：当前逐日换仓、频繁波动（近一月每天权重都变）。回测时可加"持仓天数 ≥  N 天才允许调仓"的平滑约束，降低换手成本。
- **防守态验证重点**：确认 risk_off（153 天）期间 512890 是否真的起到回撤防守作用，是 Step 3 的核心验证点。
