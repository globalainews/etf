# 容量与调用估算

## 本地SQLite实测（2026-10-26）

- 原始份额记录：1,402,412条，交易日1892日。
- 全历史 `etf_derived_daily`：1,402,412条。
- 全历史 `etf_sector_daily`：29,598条。
- 最新日ETF结果：1,690条，板块结果16条。
- 物化前 `etf.db` 约171MB，物化及建立查询索引后约1.07GB。

日常增量通常仅新增约1,700条ETF指标和16条板块指标。历史修正只替换指定起始日之后的结果，
不每日复制整个历史快照。

测算基于 2026-10-23 的本地 `etf.db`，2026-10-26 实测：1,801条基金资料、最新份额1,690条。

JSON大小来自前5,000条文档平均值估算，不含数据库内部BSON、元数据和索引。规划时建议把正文按约1.3倍、索引另按正文的0.5–1.5倍预留：90日整体约60–120 MiB，1年历史正文约98 MiB，含索引建议预留150–300 MiB。实际以控制台用量为准。

日常发布通常写入：约1,690条最新历史修订 + 约5,086条派生/板块快照；基础资料通过 `master_hash` 未变化时整批跳过，变化时才upsert 1,801条。正常日约6,800次逻辑upsert，HTTP层按80条更新合并成约90个批请求；基础资料变化日约8,600次、约110个批请求。历史修正会按明确日期边界增加写入量。

典型用户一次首页：1次云函数、约2–3次数据库查询；完整榜单翻一页：1次函数、2次查询（发布指针+榜单）；详情：1次函数、通常5次查询，历史修订较多时最多9次；自选页：1次函数、约3次查询。云函数内预计算查询不会扫描SQLite，也不会现场聚合全市场。

缓存策略：小程序可缓存最近一次真实响应及其统计日用于展示“上次成功数据”，但 real 模式失败时必须显式提示陈旧/失败，不能替换成demo。云端保留增量历史修订和最近若干派生批次；清理只按非当前 `release_id` 执行。建议至少保留最近3个成功派生批次和所有仍被历史修订链引用的数据。

价格与免费额度会变动，因此不承诺免费或某套餐必然够用。2026-10-26 核对的官方入口为 [CloudBase价格文档](https://cloud.tencent.com/document/product/876/75213)；当前文档采用资源点/套餐并存说明，正式上线前应按当日价格和真实DAU重新测算。
