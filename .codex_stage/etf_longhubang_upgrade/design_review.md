## 1. 项目定位与调用关系

四个 HTML 不是独立演示文件，也不是手工维护的静态模板。它们由 `etf_longhubang/html.py` 的 `render_pages(payload)` 动态生成，素材流水线在 `pipeline.py` 中完成数据读取、Schema/业务/安全校验、Playwright 渲染与原子发布。视频流水线在 `video.py` 中再次校验素材包，随后执行页面截图、Global CosyVoice3 配音、字幕、FFmpeg 编码与拼接；固定输出为 1080×1920、30fps。

因此本次改造保留四个文件名、JSON 契约、发布目录、`_READY.json` 和视频阶段接口，只升级生成模板、文案和视觉 QA，不改 ETF 数据库、采集脚本或视频调用入口。

## 2. 修改前评审

### 优点

- 四页职责清楚，文件名和页面顺序稳定。
- 页面自包含，无外网字体、图片或脚本依赖。
- 已有 `data-critical`、`document.fonts.ready` 和 `data-render-ready` 机制。
- 榜单数据由统一 JSON 生成，不在四份 HTML 中重复维护。
- 深蓝金融终端方向与财经栏目定位相符，首名已有有限强调。

### 主要问题与严重度

| 严重度 | 问题 | 影响 |
|---|---|---|
| 高 | 份额增加用红色、减少用绿色 | 中国证券语境中容易被误读为价格涨跌 |
| 高 | 自动截图在 ready 后固定等待 900ms | 页面动画或设备性能变化时仍存在不确定帧 |
| 高 | 收尾页只重复两个榜首 | 缺乏独立结论，最后定格的信息价值有限 |
| 中 | 封面上半部信息集中、下半部留白失衡 | 1—2 秒内的视觉路径不够明确 |
| 中 | 榜单只有数值，没有比例编码和变化率 | 难以快速判断第一名与其余名次的差距 |
| 中 | 长基金名依赖固定字号 | 极端名称可能挤压右侧数字列 |
| 中 | GLOBAL 速览与栏目名缺少明确主从关系 | 容易让主品牌抢占栏目标题层级 |
| 低 | 大量 CSS 内联但缺乏语义化变量 | 后续跨页维护和颜色审计成本偏高 |

## 3. 修改后的设计决策

### 信息结构

- 封面：`GLOBAL 速览` 作为小型母品牌，`ETF份额龙虎榜` 作为主标题；核心发现直接来自增加榜首，并保留增减榜首双卡。
- 增加榜 / 减少榜：统一 1→5，显示简称、代码、份额变化、可靠的较前日变化率和按真实绝对值缩放的水平条。
- 收尾：不再只做榜首复述，而是计算“增加榜首变化量与减少榜首绝对变化量之差”，同时用同尺度条形图比较两侧榜首，并给出统计口径和完整限定。
- 四页统一出现“自制份额统计榜”，避免被误认作交易所官方龙虎榜。

### 设计系统

| 用途 | 颜色 |
|---|---|
| 品牌主色 | `#4F8CFF` |
| 背景 | `#06101D` / `#030913` |
| 面板 | `#0B1B2D` / `#10263D` |
| 份额增加 | 青色 `#2FD3C5` |
| 份额减少 | 金色 `#F2B84B` |
| 价格上涨（保留） | 红色 `#EF5B67` |
| 价格下跌（保留） | 绿色 `#39B77A` |
| 主文字 | `#F5F8FC` |
| 次级文字 | `#9AABC0` |

份额增减不再使用红绿。红绿变量只为未来同时展示价格涨跌时预留，当前页面不使用。

标题 76—88px，核心结论 48—58px，基金名默认 40px，份额数值 47—86px，代码和统计说明 22—28px。基金名根据字符长度降至 34px 或 28px，允许自然两行，不使用省略号截断。所有数字启用等宽数字特性。

### 动画与确定性渲染

- 默认 `preview` 模式保留 0.62—0.72 秒的逐项出现与比例条展开。
- `?mode=render` 模式冻结所有 animation/transition。
- ready 条件同时等待 DOM、字体、图像，并经过双 `requestAnimationFrame` 确认布局稳定。
- Playwright 明确以 render 模式打开，不再使用固定 900ms 等待。
- QA 检查运行中动画、横纵溢出、内容安全区、字幕保留带、长名称裁切、数字列交叠、比例条缩放，并生成四张预览和 2×2 总览图。

## 4. 金融表达

- 统计公式：当日基金份额 − 前一有效交易日基金份额。
- 排名规则：增减榜分别按份额变化绝对值降序，代码升序处理并列。
- 变化率：份额变化 ÷ 前一交易日份额；分母为零时显示“变化率不可计算”，不会当作 0。
- 页面明确“份额变化不等于资金净流入，也不代表价格涨跌”。
- 不使用“机构抢筹”“资金出逃”“主力进场”等无法由份额数据证明的表述。

## 5. 现有系统约束

- 主交付包仍严格包含主 JSON 和四个 HTML；预览、总览图与 QA 记录进入审计/评审目录。
- 视频流水线依赖原 HTML 文件名和 `visual_qa.py` 生成的 `page_*.png`，因此兼容文件继续保留；新增 `preview_*.png` 为人工评审别名。
- 字幕在视频底部叠加，关键内容底边被限制在 1608px 以内，避免与字幕带重叠。
- HTML 继续自包含并拦截网络请求。

## 6. 后续改进建议

- 成片发布前抽听 ETF 专名、数字和“ETF”字母读音；这是 TTS 模型层面的人工验收点。
- 若后续需要“市场广度”“主题聚类”或“份额变化参考市值”，应先扩展可追溯数据模型，而不是从 TOP5 页面反推。
- 可在积累至少 20 个交易日后加入历史分位数或连续变化天数；当前数据库快照足以计算，但需要先定义缺失值和复权规则。
